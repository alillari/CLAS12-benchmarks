# External momentum benchmarks for CLAS12

**Proposed first comparison.** Given the clusters of one truth-associated CVT track, predict its momentum at the innermost matched MC hit. Train a Miller-style committee of scalar regressors and a Jahin-style EdgeConv graph regressor from scratch. Score both against the existing Cartesian momentum models and the stored CVT entrance estimate on the same track identities. Also run a scalar transverse-momentum comparison so the effect of extending the CMS model to three components is measurable.

This is an implementation plan. The source review covered the two v2 papers, the CMS authors' code and data archive, the CLAS12 evaluator, the v6_02 product metadata, and the saved momentum cohort keys.

### Miller reference

The simulation gives each track ten cylindrical-layer intersections, ordered by radius. Each expert sees the resulting 30 unnormalized coordinates. Six independent outputs cover transverse momentum, transverse and longitudinal offsets, longitudinal slope, and sine and cosine of the initial azimuth. Section II parameterizes the helix with pT, while Table 2 reports 1/pT residuals. Record which scalar is trained and test the reciprocal transform explicitly before comparing with the table. Use `atan2(sin, cos)` for angle recovery. Figure 5 shows three dense expansion/contraction blocks with widths 500, 2,500 and 500 and GELU at the expansion. For reconstruction, implement the blocks as drawn, record every linear dimension and initialization, and document choices the authors do not specify, such as biases. The stated training recipe uses He-normal weights, MSE, Adam at 1e-4 with betas (0.9, 0.99), batch 4,096 and 1,000 epochs, with dropout and weight decay disabled. [Fig. 5 and § IV](https://arxiv.org/pdf/2505.02937v2#page=5)

First write a small, seeded generator from § III and Table 1. Check radial intersections before smearing, both zero-mean Gaussian noise and gamma noise with a nonzero mode, and the azimuth wrap. Record the field/charge/unit convention and root choice used to find the forward intersection. Exercise all six experts, overfit a tiny noiseless sample, then compare held-out residuals with a train-mean predictor under each noise model. The paper used one million tracks and an 80/10/10 split. A small reference test validates the implementation mechanics. Reproducing Table 2 would require the full reference experiment and documented simulator assumptions. [Simulation and reference results](https://arxiv.org/html/2505.02937v2)

### Jahin reference

Use the station notebook for the compact model often cited from this paper. It reshapes 28 station measurements into four nodes with seven features each. The four EdgeConv outputs have widths 8, 12, 12 and 16. Attention pools after layers 2 and 4 feed a 28 → 22 → 16 → 16 → 1 readout. The linear layers and pooling gates give 3,005 trainable parameters in this scalar configuration. The paper also studies feature-, bending-angle- and η-centered graphs. Reserve the MPL as a separate follow-up if an edge-attribute model is needed. The modular script runs MPL with MSE. [Station notebook](https://github.com/Abrar2652/gnn-particle-momentum-cms-trigger/blob/dd073148d1578f25f76dc6d2fa9718866ccdaafe/Models/Eachstation_node/EdgeConv/each-station-edgeconv-custom.ipynb) · [Modular runner](https://github.com/Abrar2652/gnn-particle-momentum-cms-trigger/blob/dd073148d1578f25f76dc6d2fa9718866ccdaafe/Scripts/main.py) · [MPL](https://github.com/Abrar2652/gnn-particle-momentum-cms-trigger/blob/dd073148d1578f25f76dc6d2fa9718866ccdaafe/Scripts/models.py)

Three differences matter for a port.

* Table 1 calls the compact station graph fully connected. The notebook supplies 11 of the 12 directed, non-self edges, omitting 1 → 3 (zero-based). Freeze the literal 11-edge list for code parity and test the complete 12-edge interpretation separately. [Table 1](https://arxiv.org/html/2507.19205v2) · [Station notebook, graph construction](https://github.com/Abrar2652/gnn-particle-momentum-cms-trigger/blob/dd073148d1578f25f76dc6d2fa9718866ccdaafe/Models/Eachstation_node/EdgeConv/each-station-edgeconv-custom.ipynb)
* The notebook derives the scalar label as `abs(1 / (q/pt))`, removes label outliers by whole-sample IQR, fits a scaler on the filtered population (including the target), and selects checkpoints using the test loader. Use this path only to understand the source experiment. For CLAS12, fit scales on training tracks, keep the momentum tails, select on validation, and identify the target scale by column name. [Station notebook, preprocessing and training](https://github.com/Abrar2652/gnn-particle-momentum-cms-trigger/blob/dd073148d1578f25f76dc6d2fa9718866ccdaafe/Models/Eachstation_node/EdgeConv/each-station-edgeconv-custom.ipynb)
* Equations 20–22 and the executable losses differ. For instance, the code weights **relative** squared errors in its piecewise loss. In the custom loss the sigmoid expression is inside the comparison passed to `torch.gt`, after clipping the output. Keep literal-code and equation-based fixtures distinct. Test values and gradients below, at and above the lower limit. Use ordinary regression losses for the first CLAS12 fits. CMS thresholds of 80 and 160 GeV have no role in the initial CLAS12 objective. [Loss equations](https://arxiv.org/html/2507.19205v2) · [Executable loss functions](https://github.com/Abrar2652/gnn-particle-momentum-cms-trigger/blob/dd073148d1578f25f76dc6d2fa9718866ccdaafe/Scripts/losses.py)

## 3. CLAS12 model choices

| Family | Input and architecture | Supervision |
| --- | --- | --- |
| Miller committee | Sort each segment by transverse radius with deterministic xyz tie-breaks. Place every accepted hit in a fixed 100-slot xyz tensor, zero-pad and append a real-hit mask. Flatten into the Fig. 5 experts. This preserves outer hits and makes padding distinguishable from a measured zero. | Train three independent experts for entrance px, py and pz in the vector benchmark, and one expert for entrance pT in the scalar benchmark. Recompute parameter count for the changed first layer and report the cost of all three experts for the vector. |
| Jahin EdgeConv | Start with one node per measured cluster, xyz in a declared frame, and all directed non-self edges within that track. Keep the sourced layer widths, two attention pools and readout. Bound batches by total edges if needed (`N*(N-1)` per track), with gradient accumulation to preserve the effective track batch. | Change the final width to three for the vector benchmark and retain a single output for entrance pT for the scalar benchmark. Both use the same frozen track IDs. |

These are deliberate adaptations. The original Miller input always has one position per cylindrical layer. The CMS graph represents four endcap stations with hardware-specific channels such as timing, bend, ring and mask. Neither representation exists as such in the CVT cluster tensor. Start with all measured xyz so differences between the two fits can be interpreted on the existing track population. The saved 50k training lengths contain 42,481 twelve-cluster tracks and reach 46 clusters. An exactly-12 cut would change that population.

The first graph ablation, if warranted, is one node per occupied physical `(detector_id, layer)` from `cluster_meta_target`, with mean xyz and occupancy per node. Check layer coverage, repeated clusters within layers, ordering and missing layers. Tag this as a detector-metadata variant when comparing with xyz-only models. A second useful Miller check is a ten-position, deterministic radial subsample that includes both endpoints, scored on the same tracks as the all-hit model. Both ablations quantify the cost of compressing a track. If direct Cartesian experts behave differently from the toy fitter, a closer target ablation would fit entrance pT, sine and cosine of momentum azimuth, and longitudinal slope derived from the Cartesian labels. Reconstruct a vector using predicted quantities only, with an explicit policy for near-zero pT. Give reconstructed-membership fits from COATJAVA, EggNet or Exa.TrkX their own later cohort and matching/efficiency accounting.

## 4. Implementation order and acceptance checks

1. **Track manifests and evaluator.** Add track data/prediction contracts and a small CLI to prepare and audit a momentum cohort. Match the companion loader's per-track truth and CVT reference on a multi-segment fixture and on frozen real keys. Enforce one prediction per expected key, validate units and reject duplicates, missing rows and nonfinite model outputs. Verify shuffled records reassemble to identical metrics. Read a saved companion prediction set and recover its all-track and CVT-valid scores before fitting anything.
2. **Source checks.** Add separate reference specs and CLAS12 recipes. Record the paper version, CMS commit, selected files, hashes and MIT attribution in the provenance machinery when importing code. Fetch the CMS data externally for a small reference fixture. Extract just the required model code with its license. With identical seeded weights, compare notebook and port outputs and gradients on the same four-node inputs, parameter count and topology. Exercise the Miller generator and scalar experts as above. Save the resolved assumptions for both models.
3. **Trainable CLAS12 fits.** Implement both input transforms and heads behind the same per-track runner. Test input permutation/ties, padding, short and long accepted tracks, graph batching isolation, finite gradients and checkpoint reload. Overfit a small sample and run a bounded real-data pilot through training, selection, export and evaluation. Report peak memory and wall time, especially for the three dense experts. Require finite predictions and identical key/target hashes across methods before scaling up.
4. **Matched comparison.** Start at seed 42 with the existing nested 1k/50k training sets. Follow the companion starting budget of effective batch 128, 30k updates and validation every 1k. Use training-only, budget-specific target scales and standardized component MAE for the vector fit and checkpoint selection. For scalar pT, derive truth as `hypot(px, py)`, fit its own training scale and select by validation pT MAE. Give the two external models equal tuning opportunities on validation, log the selected optimizer settings, and report training resources separately. Lock recipes before final test evaluation. Repeat selected fits over multiple seeds before interpreting small differences.
5. **Report by observable and denominator.** For vectors report component and magnitude MAE, pT MAE, relative momentum bias, central width `(q84−q16)/2`, tails and direction errors including wrapped Δφ. Compare the scalar heads with pT derived from the vector heads, the companion models and CVT. Show counts and errors in true momentum, angle and cluster-multiplicity bins, including low momentum. Estimate paired uncertainty by resampling source events and report seed spread separately. If timing is reported, time full preprocessing plus inference as well as model-only forward passes on the same hardware, batch sizes and population. The papers' timing and accuracy belong to their original detectors and workloads.

Keep reusable code, recipes and tests here. Manifests containing event IDs, CMS data, checkpoints, predictions, plots and run reports belong with the external experiment artifacts. The first reviewable implementation milestone is the shared track manifest and evaluator with parity on existing predictions.
